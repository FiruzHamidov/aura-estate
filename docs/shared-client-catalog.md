# Общий каталог клиентов

Доступен стажёрам (`intern`), агентам (`agent`), РОП, МОП, администраторам и суперадминистраторам после авторизации. Отдельный API намеренно показывает подходящие потребности по всем филиалам; обычные права CRM не изменены.

- `GET /api/client-catalog/counts`: число уникальных доступных клиентов и количества по подборкам. Один клиент может попасть в обе подборки, но общий счётчик учитывает его один раз.
- `GET /api/client-catalog?list=agents|interns&search=Имя&page=1&per_page=20`: страницы каталога, до 50 клиентов за запрос.
- `agents`: от 1 млн TJS на руках, новые клиенты первыми.
- `interns`: 300–800 тыс. TJS включительно, давно добавленные клиенты первыми. Нижней границы даты нет.
- Стажёрам доступна только подборка `interns`, остальным перечисленным ролям — обе.
- Только активные покупатели/совмещённые контакты, неудалённые открытые потребности с `has_cash_on_hand=true` и валютой TJS.

DTO содержит только явно перечисленные поля потребностей, имена клиента/ответственного/филиала и дату добавления. В общих подборках телефоны, email, заметки CRM, meta и вложенные модели пользователя не сериализуются. В разрешённых текстовых полях имён, района и комментария маскируются стандартные записи телефонных номеров и email. Поиск допускает только буквы и разделители имени, поиск по скрытым контактам недоступен. Ответы `private, no-store`.

Раскрытие клиента показывает потребности без номера. Агент и стажёр могут подтвердить «Взять клиента»:

- `GET /api/client-catalog/claim-status`: доступность действия и дата обновления дневного лимита.
- `POST /api/client-catalog/{clientId}/claim`: закрепляет подходящего клиента и открытые потребности за текущим пользователем, переносит контакт в его филиал/группу, сохраняет прежние значения в журнале CRM. Закрытые потребности и создатель не изменяются.
- Разрешён один новый клиент в календарные сутки `Asia/Dushanbe`, лимит сбрасывается в 00:00. Закрывать предыдущих клиентов для следующего дня не нужно.
- Транзакция блокирует пользователя и клиента. Уникальные индексы `client_id` и `(user_id, claimed_on)` дополнительно защищают от конкурирующих запросов. Повтор того же успешного запроса не расходует лимит снова.
- Взятый клиент исчезает из обеих общих подборок и бейджа. История получения сохраняется при удалении/передаче контакта и не освобождает дневной лимит.
- `GET /api/client-catalog/mine`: ранее взятые текущим пользователем клиенты с телефоном; доступ сохраняется только пока сотрудник остаётся ответственным. РОП/МОП/администраторы просматривают общий каталог, но не участвуют в получении.
- В каталоге телефон возвращается только ответом успешного закрепления и в «Мои из каталога». Обычные CRM-права руководителей и других сотрудников с уже существующим доступом к контакту не изменены.

## Выпуск

Согласовать выпуск с frontend-веткой `ff/client-catalog-claim`. Сначала доступный backend API, затем frontend. До запуска нового API применить миграцию `2026_09_29_120000_create_client_catalog_claims_table.php`. Она создаёт пустой журнал получения; существующие клиенты автоматически взятыми не считаются. При откате кода таблицу и историю сохранять, чтобы не потерять лимиты. После выпуска проверить авторизованное открытие каталога и реальный бейдж агентом/стажёром; гостевой запрос и чужие роли должны получать 401/403.

## Проверки

`ClientNeedPropertyTypeFilterTest` покрывает каталог, дедупликацию, права ролей, маскировку контактов, сохранение обычных прав CRM, пагинацию и старые записи первыми. Вместе с `ClientAccessTest`: 77 тестов, 519 проверок. Дополнительно проверены закрепление, отказ чужим ролям, суточная граница Душанбе, безопасный повтор, уникальные индексы, откат транзакции и отзыв телефона при смене ответственного. В фикстуру существующего теста прав добавлены отсутствовавшие таблицы видов ремонта, используемые текущей сериализацией ClientNeed.
