# Дата содержательного обновления объекта недвижимости

## Цель

Добавить отдельную дату последнего содержательного обновления объявления, не меняя назначение существующих системных дат:

- `created_at` — первоначальная дата добавления объекта, неизменяемая после создания;
- `updated_at` — техническая дата Laravel, используемая внутренними процессами и синхронизациями;
- `listing_updated_at` — дата последнего изменения публичного содержания объявления.

## Требования к базе данных

В таблицу `properties` добавляется nullable-колонка `listing_updated_at` типа `timestamp` и индекс для сортировки. Существующие записи заполняются своим значением `created_at` пакетами. Во время переходного периода API использует `created_at`, если `listing_updated_at` ещё не заполнено.

Новые объекты получают `listing_updated_at`, равное времени создания. Поле `created_at` не перезаписывается ни миграцией, ни последующими обновлениями.

## Когда дата обновляется

`listing_updated_at` меняется после успешного фактического изменения публичного содержания:

- основных параметров: заголовка, описания, цены, валюты, типа предложения;
- типа, статуса/характеристики объекта, адреса и местоположения;
- площади, этажей, количества комнат, года постройки;
- состояния, ремонта, отопления, парковки и других публичных параметров;
- ссылок, характеристик и тегов;
- состава или порядка фотографий;
- типа размещения (`regular`, `vip`, `urgent`).

Повторное сохранение тех же значений не меняет `listing_updated_at`.

## Когда дата не обновляется

Дата содержательного обновления не меняется при:

- просмотре объявления и увеличении `views_count`;
- изменении модерации без изменения публичного содержания;
- продаже, аренде, депозите, комиссии и других параметрах сделки;
- изменении владельца/ответственного, внутренних комментариев и служебных связей;
- фоновой синхронизации, создании логов и техническом обновлении `updated_at`.

## API

Ответы списка, поиска, создания, редактирования и детальной карточки содержат обе бизнес-даты в ISO 8601:

```json
{
  "created_at": "2026-08-01T10:00:00.000000Z",
  "listing_updated_at": "2026-08-14T10:30:00.000000Z"
}
```

`listing_updated_at` является серверным read-only полем и не принимается из формы.

Для `GET /api/properties` и `GET /api/my-properties` поддерживается сортировка:

```text
sort=listing_updated_at&dir=desc
```

Существующие фильтры и сортировка по `created_at` сохраняют прежнее поведение.

## Требования к интерфейсу

В клиентском приложении в карточке объекта отображаются:

```text
Добавлено: 1 августа 2026
Обновлено: 14 августа 2026, 15:30
```

Если `listing_updated_at` равно `created_at`, строка «Обновлено» может быть скрыта. В списке объектов дата добавления остаётся основной, а дата обновления показывается вторичной подписью. При необходимости интерфейс может использовать новый параметр сортировки «Недавно обновлённые».

Laravel API и пользовательский интерфейс находятся в отдельных репозиториях. Клиентская реализация выполнена в `aura-front`: поле добавлено в тип `Property`, даты отображаются в общей карточке объекта и на детальной странице, а `listing_updated_at` используется как `dateModified` в структурированных данных.

## Обратная совместимость

Без изменений должны продолжить работать:

- отчёты, KPI и фильтры, основанные на `created_at`;
- существующая сортировка новых объектов;
- технические интеграции, основанные на `updated_at`;
- существующие поля и структура API.

Ни один существующий процесс не переводится на `listing_updated_at` автоматически.

## Критерии приёмки

1. После любого редактирования `created_at` остаётся прежним.
2. Содержательное изменение обновляет `listing_updated_at`.
3. Сохранение без фактических изменений не обновляет `listing_updated_at`.
4. Изменение характеристик, тегов, фотографий или их порядка обновляет дату.
5. Просмотр, модерация и параметры сделки не обновляют дату.
6. Старые объекты возвращают корректную дату, первоначально равную `created_at`.
7. API возвращает поле в списке, поиске и детальной карточке.
8. Сортировка по `listing_updated_at` работает в обоих направлениях.
9. Существующие сценарии по `created_at` и `updated_at` не меняют поведение.
