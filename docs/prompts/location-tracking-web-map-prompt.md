# Готовый промпт для сайта: карта сотрудников и история перемещений

Скопируй весь текст ниже в отдельную задачу frontend-разработчику или coding agent.

---

Ты работаешь над существующим web-приложением Aura Estate. Реализуй production-ready раздел «Карта сотрудников» для наблюдения за доступными агентами и МОПами, выбора одного или нескольких пользователей и просмотра истории их перемещений линиями на карте.

Сначала изучи frontend-проект:

- framework и router;
- auth/session и формат текущего пользователя;
- API client;
- state/query library;
- UI kit и дизайн-токены;
- существующий map provider;
- обработку 401/403/422/429;
- тестовый стек.

Не создавай второй API client, второй UI kit или отдельный стиль приложения. Если map provider уже используется, продолжай использовать его. Если карты ещё нет, предпочтительно использовать Leaflet с подходящим production tile provider. Не размещай секретный API key в frontend-коде.

Backend уже реализован. Полный контракт находится в:

```text
docs/user-location-tracking-spec.md
```

## Цель

Создать удобный экран, на котором руководитель:

- видит доступных ему сотрудников на карте Душанбе и других городов;
- выбирает одного или нескольких сотрудников;
- быстро находит сотрудника по имени;
- фильтрует по роли, филиалу, группе и статусу;
- сохраняет личный список «кого смотреть»;
- видит последнюю позицию и её свежесть;
- открывает историю за период;
- видит путь каждого выбранного пользователя отдельной цветной линией;
- понимает, откуда пользователь начал движение и где закончил;
- видит время, точность и подпись каждой точки;
- может включать и выключать отображение отдельных маршрутов.

## Права

Frontend ничего не решает самостоятельно и использует backend scope:

- `agent` — только себя;
- `mop` — себя и агентов своей группы;
- `rop`, `branch_director` — агентов и МОПов своего филиала;
- `admin`, `superadmin` — глобальный доступ;
- остальные роли — раздел скрыт.

Скрытие раздела не заменяет backend-проверку.

## API

### Список доступных сотрудников

```http
GET /api/location-tracking/available-users
```

Query:

```text
search
role=agent|mop
branch_id
branch_group_id
tracking_enabled
page
per_page
```

### Настройка выбранных пользователей

```http
GET /api/location-tracking/watchlist
PUT /api/location-tracking/watchlist
```

Payload:

```json
{
  "mode": "selected",
  "user_ids": [1, 15, 27]
}
```

Режимы:

- `all_available`;
- `selected`.

### Текущая карта

```http
GET /api/location-tracking/map
```

Фильтры:

```text
role
branch_id
branch_group_id
status
```

Каждый элемент содержит:

```json
{
  "user": {
    "id": 1,
    "name": "Admin User",
    "photo": null,
    "role": "admin",
    "branch_id": null,
    "branch_group_id": null
  },
  "tracking": {
    "enabled": false,
    "status": "tracking_disabled"
  },
  "location": {
    "latitude": 38.5559,
    "longitude": 68.7961,
    "accuracy_m": 17,
    "quality": "good",
    "captured_at": "2026-07-29T11:30:00Z",
    "received_at": "2026-07-29T11:30:02Z"
  }
}
```

Даже если tracking сейчас выключен, сохранённую демо-позицию можно показывать с честным статусом и временем.

### История пользователя

```http
GET /api/location-tracking/users/{userId}/history?from={ISO}&to={ISO}&quality=
```

Период обязателен, максимум 31 день. Точки отсортированы backend’ом по `captured_at ASC`.

Демо-точки содержат:

```json
{
  "latitude": 38.5783,
  "longitude": 68.7866,
  "accuracy_m": 11,
  "captured_at": "...",
  "quality": "good",
  "meta": {
    "demo": true,
    "sequence": 4,
    "label": "Район парка Рудаки",
    "city": "Душанбе"
  }
}
```

## Desktop-композиция

Экран разделить на три функциональные зоны:

1. Верхняя панель:
   - заголовок;
   - дата/период;
   - режим «Сейчас / История»;
   - фильтры;
   - время последнего обновления;
   - кнопка обновления.
2. Левая панель шириной 320–380 px:
   - поиск;
   - «Все доступные / Выбранные»;
   - массовый выбор;
   - список сотрудников с checkbox;
   - роль, группа и статус;
   - цвет маршрута пользователя;
   - переключатель видимости маршрута.
3. Карта занимает оставшееся пространство:
   - текущие маркеры;
   - исторические polylines;
   - start/end markers;
   - tooltips;
   - легенда;
   - control «показать всех выбранных».

Минимальная высота карты — `calc(100vh - header)`. Не помещай карту в маленькую карточку.

## Mobile/tablet

- список сотрудников открывается bottom sheet или drawer;
- фильтры — отдельный sheet;
- карта остаётся основной поверхностью;
- карточка выбранного пользователя открывается снизу;
- не показывай широкую desktop-таблицу;
- все интерактивные элементы не меньше принятого в проекте touch target.

## Выбор пользователей

Нужно поддержать:

- один пользователь;
- несколько пользователей;
- выбрать всех доступных;
- снять всех;
- выбрать агентов;
- выбрать МОПов;
- выбрать филиал;
- выбрать группу;
- поиск по имени/телефону;
- включить/выключить конкретный маршрут без удаления из watchlist.

Различай:

- `watchlist selection` — сохраняется на backend;
- `visible on current map` — локальное UI-состояние текущего экрана.

Не отправляй `PUT /watchlist` при каждом клике без debounce. Используй кнопку «Применить» либо debounce и optimistic UI с rollback.

Если backend возвращает `LOCATION_INVALID_WATCHLIST`, обнови available-users и объясни, что структура доступа изменилась.

## Текущие позиции

Для каждого пользователя:

- маркер с фото или инициалами;
- имя;
- роль;
- время координаты;
- возраст точки;
- accuracy;
- quality;
- tracking status.

Цвет статуса:

- `live` — зелёный;
- `stale` — жёлтый;
- `offline` — серый;
- `no_data` — пустой/нейтральный;
- `permission_denied` — красный контур;
- `background_permission_missing` — оранжевый;
- `outside_schedule` — синий/нейтральный;
- `tracking_disabled` — серый.

Пользователь с `location=null` остаётся в боковом списке, но не создаёт маркер `(0,0)`.

Никогда не называй устаревшую позицию «сейчас». Показывай «Последняя позиция N минут/часов назад».

## История и линии маршрута

При переходе в режим «История»:

1. Пользователь выбирает дату или период.
2. Для каждого видимого выбранного сотрудника выполняется history-запрос.
3. Ограничь параллелизм запросов, например 4 одновременно.
4. Каждому user ID назначь стабильный цвет.
5. Построй polyline строго в порядке `captured_at ASC`.
6. Не выполняй frontend road snapping и не называй линию автомобильным маршрутом.
7. Начальную точку отметь зелёным маркером «Старт».
8. Конечную точку отметь красным маркером «Финиш».
9. Промежуточные точки показывай небольшими точками либо только при zoom.
10. По клику на точку покажи:
    - `meta.label`, если есть;
    - порядковый номер;
    - время;
    - accuracy;
    - quality;
    - координаты с ограниченным количеством знаков.

Если между точками большой временной разрыв, например более 15 минут:

- не создавай впечатление непрерывного движения;
- раздели polyline на сегменты либо покажи разрыв пунктиром;
- tooltip: «Нет данных N минут».

Для `quality=suspect`:

- отдельный стиль;
- не включать точку в обычную линию либо показывать пунктиром согласно UX проекта;
- подпись «Подозрительная GPS-точка».

Для нескольких пользователей:

- отдельный цвет линии;
- легенда `цвет → пользователь`;
- checkbox видимости;
- fit bounds по всем видимым маршрутам;
- не перерисовывай всю карту при открытии tooltip.

## Демо пользователя ID 1

Добавь development-only быстрый сценарий:

- кнопка или story «Показать демо-маршрут ID 1»;
- доступна только в development/demo build либо по feature flag;
- выбирает пользователя `id=1`;
- включает режим «История»;
- устанавливает период, включающий сегодняшний день;
- вызывает:

```http
GET /api/location-tracking/users/1/history?from={startOfTodayISO}&to={endOfTodayISO}
```

- строит линию по Душанбе;
- показывает 14 точек;
- подписывает точки из `meta.label`;
- выделяет старт и финиш;
- автоматически делает fit bounds;
- последняя точка также отображается на current map.

Не hardcode координаты демо-маршрута во frontend. Источник — только API.

## Работа с картой

- начальный центр без маркеров: Душанбе `38.5598, 68.7870`;
- начальный zoom выбери для уровня города;
- если есть точки — используй fit bounds с разумным padding;
- при одной точке используй фиксированный zoom;
- clustering применять только для текущих маркеров при большом количестве;
- history points одной линии не кластеризовать;
- сохранять выбранный base layer только если это соответствует текущим настройкам приложения;
- attribution map provider обязательно оставить видимым.

## Polling и cache

Режим «Сейчас»:

- polling `/map` каждые 30 секунд;
- останавливать polling, когда вкладка скрыта;
- немедленно обновлять при возврате вкладки;
- сохранять предыдущие данные во время refetch, чтобы маркеры не мигали;
- не анимировать резкий прыжок старой точки как реальное движение.

Режим «История»:

- polling не нужен;
- history cache key включает user ID, from, to и quality;
- отменять устаревшие запросы при смене периода;
- не запрашивать одного пользователя повторно без изменения параметров.

## Состояния интерфейса

Реализуй:

- loading skeleton списка;
- loading overlay карты без её демонтажа;
- пустой scope;
- пустой watchlist;
- нет координат;
- нет истории за период;
- частичный сбой одного маршрута при успешных остальных;
- 401 session expired;
- 403 role/scope;
- 422 слишком большой период;
- 429 retry countdown;
- offline banner.

При частичном сбое нескольких history-запросов не скрывай успешно загруженные маршруты.

## Приватность

- точные координаты не отправлять в analytics;
- не писать API response в console;
- не помещать координаты в URL браузера;
- не сохранять историю в localStorage;
- очищать query cache при logout;
- не показывать координаты в публичных страницах;
- export не реализовывать, пока нет отдельного backend permission;
- frontend не должен обходить scope прямым запросом чужого ID.

## Тесты

Обязательные сценарии:

1. Загружается список доступных пользователей.
2. Можно выбрать одного пользователя.
3. Можно выбрать несколько пользователей.
4. Watchlist сохраняется и восстанавливается.
5. `location=null` не создаёт маркер.
6. Live/stale/offline отображаются разными статусами.
7. История сортируется по времени.
8. Строится отдельная линия для каждого пользователя.
9. Старт и финиш отображаются корректно.
10. Временной разрыв разделяет линию.
11. Ошибка одного history request не удаляет другие маршруты.
12. Scope error не раскрывает данные пользователя.
13. Polling работает только в режиме «Сейчас» и при видимой вкладке.
14. Demo ID 1 строит маршрут из API и показывает `meta.label`.
15. Logout очищает координаты из query cache.
16. На mobile открывается drawer/bottom sheet, карта остаётся доступной.

Для map library используй test adapter/mock, не проверяй пиксели сторонней карты.

## Definition of Done

- страница встроена в существующие router/navigation/RBAC;
- один и несколько пользователей выбираются удобно;
- current markers и historical polylines работают;
- маршруты имеют стабильные разные цвета;
- старт, финиш, разрывы и подписи видны;
- watchlist сохраняется;
- demo user ID 1 отображается по данным сидера;
- карта адаптивна;
- нет координат в logs, analytics и localStorage;
- тесты проходят;
- добавлен краткий README с настройкой map provider;
- итоговый отчёт содержит изменённые файлы, команды запуска, тесты и screenshots desktop/mobile.
