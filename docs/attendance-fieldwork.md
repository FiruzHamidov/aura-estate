# Отметки рабочих выездов ZKTeco

С 28.09.2026 00:00 Asia/Dushanbe аппараты используют следующие пункты:

| Код | На аппарате | Событие API | Состояние сотрудника |
| --- | --- | --- | --- |
| 0 | Приход | `check_in` | В офисе |
| 1 | Уход | `check_out` | Ушёл |
| 2 | Показ | `showing_out` | На показе |
| 3 | С показа | `showing_in` | В офисе |
| 4 | Объект | `property_out` | На приёме объекта |
| 5 | С объекта | `property_in` | В офисе |

Порог задаёт `ATTENDANCE_FIELDWORK_STARTED_AT` (по умолчанию
`2026-09-28T00:00:00+05:00`). Классификация использует время самой отметки,
поэтому поздняя загрузка старых данных с отключённого аппарата сохраняет
старый смысл кодов. `ATTENDANCE_FIELDWORK_DEVICE_SERIALS` ограничивает новую
схему перечисленными через запятую серийными номерами. Пустое значение
означает все аппараты; перед выпуском сверить список с перенастроенными
терминалами. Более ранняя история продолжает использовать `status_map`.

Показы и приём объектов не создают приход/уход и не вычитаются из рабочего
времени. Первый приход и последний уход по-прежнему определяют границы дня.
Старые перерывы по-прежнему вычитаются. Разные действия в пределах десяти
секунд не считаются дублями друг друга.

`activity` в матрице и деталях дня содержит последнее состояние, время его
начала, последнюю отметку и число выездов каждого вида. Используются только
доступные просматривающему события этого дня, без дублей и будущих отметок.
Это состояние по терминалу, а не геолокация. Без отметок место неизвестно.

## Выпуск и ранее полученные данные

1. Сначала выпустить совместимый frontend: старый интерфейс не знает новых
   типов событий. Новый frontend принимает старые ответы без `activity`.
2. Выпустить backend штатным процессом и проверить настройки порога/аппаратов.
3. Просмотреть пересчёт: `php artisan attendance:reclassify-fieldwork`.
4. Применить: `php artisan attendance:reclassify-fieldwork --apply`.
5. Проверить детали дня и матрицу для сотрудника с показом/приёмом объекта.

Команда меняет только события начиная с порога и до времени запуска на
указанных аппаратах. Коды берутся из сохранённого `meta.attendance_status`;
события без исходного кода не угадываются. Переопределяются тип, направление
и признак дубля, затем пересчитываются затронутые дни. Оригинальные сырые
отметки не изменяются. Каждое изменение сохраняется в attendance audit log.
Транзакция и блокировка сотрудника совпадают с ingestion; повторный запуск
без новых данных не меняет события и не добавляет записи аудита.
