# Модерация объявлений: реализация и запуск

Исходные требования: [PROPERTY_MODERATION_ANTI_ABUSE_TZ.md](PROPERTY_MODERATION_ANTI_ABUSE_TZ.md).

## Устройство

- `PropertyModerationService` применяет правила публикации, одобренные снимки, кейсы, решения по дублям, отзыв, апелляции и передачу объекта.
- `PropertyModerationAccess` отвечает за allowlist ролей, область доступа и запрет самоподтверждения. Все участники изменения открытого кейса учитываются через события, исходный автор сохраняется.
- `PropertyPromotionService` управляет заявками, независимым одобрением, сроками и приостановкой продвижений.
- `PropertyModerationNotifier` сохраняет уведомления с ключами дедупликации. Повторное событие не сбрасывает состояние прочтения.
- `Property::publicSearchable()` определяет доступность для публичных запросов. Списки, прямой запрос, карта, reels, подборки, избранное и badges используют серверную проверку доступности.
- `EnsurePropertyModerationIdempotency` связывает ключ с пользователем, маршрутом, данными и содержимым загруженных файлов. Успешная мутация и сохранение ответа выполняются в общей транзакции.

Обычные формы не отправляют публикационный статус, продвижение или владельца записи. Изменения формы, удаление фото и порядок фото сохраняются вместе. Версия берётся из объекта, на основе которого открыта форма, поэтому фоновое обновление данных не разрешает сохранение устаревшей формы.

## Правила, важные для поддержки

1. Чистое объявление автоматически публикуется как regular. Кандидаты в дубли и замечания качества создают блокирующие кейсы.
2. Повышение сравнивается с одобренной ценой. Разрешённое снижение становится новым ценовым снимком, но не обнуляет накопленные изменения описания.
3. Существенные изменения во время pending также создают кейс. Отзыв цены или одобрение другого кейса не публикует непроверенный контент.
4. Отклонённое предложение остаётся блокирующим до исправления/повторной отправки, отзыва или положительной апелляции.
5. Общий отзыв кейса не разрешает дубли. Отзыв изменений сохраняет независимую проверку дублей; подтверждённый дубль разрешается только специализированными действиями.
6. Снимок кандидата в дубли не перезаписывается при последующих поисках. Merge сохраняет первоначальное решение о подтверждении и его автора.
7. Файлы одобренных фото сохраняются для восстановления, в том числе после нескольких удалений в pending. Аудит содержит ID, пути, позиции и SHA-256 содержимого; для отсутствующего файла hash равен null.
8. Продвижение вычисляется по действующей записи и публичности объекта. Истечение срока проверяется при чтении, даже до запуска планировщика. Общее одобрение не возобновляет suspended-продвижение.
9. Карта и серверная страница `/apartment/[slug]` не кэшируют решение о публичности. Уже открытая у посетителя страница не может быть удалена из памяти его браузера, но последующие запросы проходят текущую серверную проверку.

## Развёртывание

Изменения затрагивают два репозитория: `aura-estate` и `aura-front`. Обновлять backend и frontend следует согласованно: старые клиенты, отправляющие защищённые поля, получат 422; старое окно смены статуса выведено из эксплуатации.

Перед применением миграции сохранить резервную копию БД и выполнить отчёт на целевом окружении:

```sh
php artisan properties:moderation-audit --days=90 --limit=10000
```

Миграция функциональности:

```sh
php artisan migrate --path=database/migrations/2026_09_04_100000_add_property_moderation_workflow.php --force
```

Миграция переносит старые состояния в публикационные и сделочные, формирует исходные одобренные снимки. Старые VIP/«Срочно» переводятся в regular; для опубликованных объектов с существующим автором создаётся заявка ретроспективной проверки с `source=system_backfill`. Старый флаг продвижения сам по себе не считается решением модератора.

Переменные конфигурации перечислены в `.env.example`. Порог повышения по умолчанию — 0%. После изменения конфигурации обновить config cache штатным процессом развёртывания.

Laravel scheduler должен работать. Команда `properties:expire-promotions` зарегистрирована с периодом пять минут; разовый запуск:

```sh
php artisan properties:expire-promotions
```

Обновить frontend production-сборкой. Очередь доступна по `/profile/moderation`, включает страницы кейсов, продвижений и рейтинга. После миграции проверить ретроспективные заявки.

Rollback миграции удаляет новые таблицы и историю процесса. Для возврата версии после работы пользователей использовать резервную копию и согласованный план восстановления, а не обычный `migrate:rollback`.

## Проверка

```sh
php -d memory_limit=1G vendor/bin/phpunit
```

Целевые тесты: `PropertyModerationWorkflowTest`, `PropertyConstructionFieldsTest`, `ExternalPropertyRequestFeatureTest`. Они включают реальные HTTP-запросы CRUD/action, idempotency replay, устаревшие версии, скрытый объект для клиента, последовательные изменения, неизменяемые доказательства, восстановление фото и реальный backfill/rollback миграции.

В `aura-front`:

```sh
npx tsc --noEmit
node --test services/add-post/submissionGuard.test.ts
npm run test:ct -- property-duplicate-review.spec.tsx
npm run build
```

Автотесты backend используют SQLite. Проверка блокировок и одновременных транзакций на СУБД целевого окружения остаётся частью staging-проверки; тест устаревшей версии не заменяет нагрузочную проверку MySQL/PostgreSQL. Рабочая БД при разработке этих изменений не мигрировалась.
