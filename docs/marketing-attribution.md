# Маркетинговые лиды и продажи

Отчёт `GET /api/crm/marketing-leads` доступен из списка заявок; краткие показатели — в профиле и списке пользователей. Даты выбирают поступление лидов, а горизонт 30/60/90 дней — срок наблюдения за каждым из них. Временная зона Asia/Dushanbe. Период ограничен годом и 5000 заявками; при превышении API просит сузить фильтр, а не возвращает неполную статистику.

## Правила

- Источник, кампания, нормализованный номер и время поступления фиксируются при создании маркетологом, подтверждённом серверном приёме с сайта либо явной отметке администратора. Изменение карточки не переписывает происхождение.
- По ранее существовавшим лидам/клиентам определяется категория «повторная заявка»/«был в базе». Руководитель может подтвердить возврат благодаря новой кампании с обязательным обоснованием; исходная категория сохраняется. Это не новый привлечённый контакт.
- История назначений сохраняет получателя, время передачи и инициатора. Полученные и обработанные номера считаются уникально для каждого агента. Обработка засчитывается ему только во время его назначения; продажи — фактическому продавцу объекта. У нескольких агентов может быть один полученный номер, поэтому суммы строк не равны общему числу номеров.
- Работа — звонок, задача со статусом done и результатом, либо отметка проведённого показа. Запланированная встреча, открытие карточки, смена статуса и конвертация лида в сделку не считаются продажей. Контакт состоялся только при результате connected или проведённом показе. Все эти действия являются ручными отметками CRM, а не подтверждением телефонией.
- Продажа — объект в статусе sold с датой после поступления и в пределах срока наблюдения. Прямая уникальная цепочка «лид → сделка → объект», совпадающая с клиентом-покупателем, подтверждается автоматически. Совпадение номера или клиента без такой цепочки — кандидат для проверки руководителем. Решение с обоснованием сохраняется в аудите. Одна продажа закрепляется за одним лидом; отклонённую связь можно пересмотреть. При отмене продажи объект перестаёт учитываться.
- Конверсия — уникальные номера покупателей / уникальные полученные номера. Общая конверсия предварительная; отдельно показан показатель для заявок с завершённым сроком наблюдения. Пустые телефоны не входят в знаменатель. Доход берётся из actual_company_income единственной связанной сделки, по валютам раздельно. Он отражает заполненные данные CRM, не поступление денег в бухгалтерии.
- Admin/superadmin/marketing видят весь отчёт; руководитель филиала — филиал, РОП — свои группы, агент — доступные ему лиды и собственные продажи. Отчёты разных областей доступа нельзя напрямую сравнивать. Проверять связи могут admin/superadmin/branch_director/rop. Доступ к другим финансовым отчётам маркетологу не расширен.

## Подготовка выпуска

1. Выпустить backend и выполнить `php artisan migrate --force` до включения новой страницы frontend.
2. Миграция `2026_10_14_110000_backfill_marketing_lead_receipts` вызывает `marketing:backfill-leads` для прежних маркетинговых лидов. Команда повторяемая; прежние назначения не восстанавливает, а помечает текущую фиксацию исторической. Если роль создателя или источник старого лида менялись, такой импорт требует проверки: точной истории до запуска учёта нет.
3. Выпустить frontend. Проверить отчёт под руководителем и агентом, форму ручного звонка/показа и краткие показатели пользователей.

Реализация не включает телефонию, автоматическую проверку содержания звонка или объединение клиентов с разными номерами. Передача в другой филиал сохраняется в общей истории, но видимость прежнему агенту по-прежнему определяется действующими правами CRM.
